## Описание модели

- Город (`class City`) характеризуется набором перекрестков и дорог (`class CrossRoad`, `class Road`)
- Каждая дорога начинается в перекрестке и заканчивается в другом перектестке
- Каждая дорога имеет двухстороннее движение
- На перекреске имеется 4 порта `[0, 1, 2, 3]`, к которым подключается дорога (не обязательно ко всем 4), движение управляется светофором
- На каждом $i$-ом перекрестке стоит своя упрощенная модель светофора: $t_i$ секунд он пропускает машины в портах `[0, 2]`, а потом $t_i$ секунд он пропускает машины в портах `[1, 3]`
- Машины (`class Vehicle`) работают по следующему правилу: генерируется случайный маршрут (может даже по одной дороге туда-обратно) и скорость, которая в среднем равна 27.5 км/час. На перекрестке, если светофор красный, то машина стоит.
- По окончании маршрута, машина удаляется из симуляции
- Есть возможность сделать так, чтоб каждые $n$ секунд в городе появлялась новая машина
- 1 единица машины может быть интерпретирована как набор машин (для постобработки)
- Во время симуляции, на каждом шаге временной сетки собирается статистика количества единиц машина на каждом участке дороги для анализа в постобработке

## 1. Определение загруженности участков

В параметры симуляции включены настройки: `sim_duration` - полное время симуляции в секундах и настройка `delta_t` - шаг симуляции в секундах. На каждом шаге в симуляции:
- продвигаются машины (если не стоят на красном светофоре перекрестка)
- меняются состояния светофоров
- появляются новые машины со своими маршрутами (раз в `car_spawn_rate` секунд) / исчезают машины, завершившие заложенный в них маршрут
- записывается сколько машин находится на каждой дороге в данный момент времени

На выход симуляция отдает набор таймстэмпов `time_vec` и состояния дорог `road_state` - количество машин на каждой дороге в каждый момент времени

Далее эти сырые данные обрабатываются в пост-процессоре (`class PostProcessor`). Пост-процессор работает по следующему алгоритму:
1. Находит 10 самых нагруженных дорог в начальный момент времени `time_vec[0]`
2. Строит графики зависимости количества машин на отобранных дорогах с течением времени. Пример:
![roads_evolution](load_evolution_plot.png)
3. Считает процент машин от общего числа в каждый момент времени на отобранных 10 участках
4. Ищет момент времени, когда загруженность этих участков стала ниже `thrreshold` процентов и резюмирует это в графике вида:
![load_percentage](load_percentqage_plot.png)
5. Также строит для каждой дороги среднее количество машин на протяжении симуляции:
![mean loads](mean_load.png)

Для работы в описанном режиме необходимо запустить файл [`run_single_sim.py`](../src/run_single_sim.py).

## 2. Оптимизация загруженности с помощью написанной модели

Оптимизация работы транспортной системы не может предполагать какие-то изменения в поведении автомобилей. Она может предполагать только изменения параметров взаимодействия элементов города между собой. В модели элементов 2 - перекрестки и дороги. Их взаимодействие управляется светофорами, которые параметризуются временем между сменой состояния `зеленый / красный`. На каждом светофоре это время свое. Оптимизацию можно проводить как раз по этим параметрам.

Для работы в описанном режиме необходимо запустить файл [`run_optimization.py`](../src/run_optimization.py).

**Целевая функция для оптимизации:**

Пусть $\mathbf{\tau}={\tau_0, \tau_1, ..., \tau_{n-1}}$ - длительности светофоров на всех $n$ перекрестках. В начальный момент времени симуляции определяется топ-10 самых загруженных участков. Суммарное количество машин на этих 10 участках отнечсенное к общему количеству тактивных машин в городе в данный момент времени будем обозначать функцией $P(t)$. Введем функцию $f(t)=P(t)/P(t=0)$ - она показывает насколько с течением времени рассасывается (или нарастает) поток машин на изначально самых загруженных участках. Определим время рассасывания потока машин как:

$$t_{er} = \min\{t: f(t)=w\}$$

где $w\in[0, 1]$ - доля в которую должна уменьшиться нагрузка улиц.

Соответственно $t_{er}$ будет зависеть от длительности каждого светофора, поэтому для оптимизации будет решаться следующая задача:

$$\mathbf{\tau_{opt}}=\argmin\limits_{\mathbf{\tau}} t_{er}(\tau)$$

То есть будем подбирать такие длительности светофоров, чтоб минимизировать время рассасывания машин при заданном коэффициенте $w$.

**Метод оптимизации:**
Так как каждый параметр ${\tau_0, \tau_1, ..., \tau_{n-1}}$ является независимым и может принимать любые значения, то единственный вариант получения оптимального решения - полный перебор по всем значениям параметров (сложность оценена в разделе 3). Такой вариант вычислительно трудно реализуемый.

Для редукции вычислительной сложности предлагается ввести следующие ограничения (из здравого смысла):
- длительность сигнала должна быть целым числом секунд, чтоб было удобно реализовывать таймер на дисплее светофора
- длительность сигнала не может быть меньще 16 секунд, чтоб пешеходы и автомобили успевали проезжать (расстояния на перекрестках не учитываются в модели, тк считается, что оно принебрежительно мало по сравнению с длиной улицы)
- длительность сигнала не должна быть больше 41 секунды (тут нет здравого объяснения, кроме как ,чтоб пешеходы и водители не нервничали)

Однако задача остается вычислительно невыполнимой. нужно перебрать $(41-16)^{33}=25^{33}$ вариантов. Поэтому можно сильно упростить количество прогонов модели, сделав метод случайного подбора вектора $\tau$ (за $q$ итераций). Такой метод не гарантирует попадание в глобальный минимум, но точно попадет в минимум некоторого подмножества вариантов.

Зависимость значения целевой функции от числа итераций при оптимизации:
| $q$ | $t_er$, сек |
|:----|:------------|
| 10  | 231         |
| 20  | 168         |
| 40  | 105         |


## 3. Вычисление сложности работы симуляции

Введем параметры:

|Параметр   | Описание |
|:----------|:--------------------------------------------------------------------------------------|
|$N_{cars}$ | Среднее количество машин в симуляции                                                  |
|$N_{roads}$| Число дорог в модели                                                                  |
|$N_{nodes}$| Число перекрестков в городе                                                           |
|$k_{time}$ | Число временных точек, обсчитывающихся в симуляции. Равно `int(sim_duration/delta_t)` |

Для каждой задачи будем оценивать память $M$ и время $T$:

1. Однократная симуляция (нужно хранить все дороги, перекрестки, машины и моменты времени, на каждом шаге нужно обсчитавать движение каждой машины и менять состояния светофоров):

$$M_{sim}=O(N_{roads} + N_{nodes} + N_{cars} + k_{time} + N_{roads}\cdot k_{time}) = O(N_{roads}\cdot k_{time}) \qquad T_{sim}=O(k_{time}(\cdot N_{cars} + N_{nodes}+N_{roads}))$$

2. Оптимизация с полным перебором (grid search):

$$M_{gs}=M_{sim} \qquad T_{gs} = T_{sim}\cdot m^{N_{nodes}} = O(k_{time}(\cdot N_{cars} + N_{nodes}) \cdot  m^{N_{nodes}})$$

$m$ - количество значений длительности одного сигнала, которые может принимать светофор на каждом перекрестке.

3. Оптимизация со случайным подбором (randomized search):

$$M_{rs}=M_{sim} \qquad T_{rs} = T_{sim}\cdot q = O(k_{time}(\cdot N_{cars} + N_{nodes}) \cdot  q)$$

$q$ - количество итераций запуска случайного подбора параметров.

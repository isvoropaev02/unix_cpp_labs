### Выбор алгоритма, сложность, память:

Так как о распределении исходных данных нет априорной информации, желательно взять алгоритм, который одинкаово хорошо работает в ситуциях, когда массив близок к отсортированному по возрастанию/убыванию и в промежуточных случаях.

Таким алгоритмом может являться quick-sort. Средняя асимптотика его сложности равна $O(n\cdot \log n)$, где $n$ - размер массива (показано ниже).

**Оценим сложность алгоритма по мастер-теореме:**

Обозначения: $T(n)$ -время, требующееся алгоритму для сортировки $n$ элементов, $M(n)$ - память затраченная алгоритмом на сортировку $n$ элементов.

Так как сортировка происходит *in-place*, дополнительные затраты включают только память на хранения стека рекурсивных вызовов. Поэтому $M$ также будет показывать глубину рекурсии.

1. В *среднем* и, заодно, *лучшем* случае массив на каждом шаге алгоритма будет делиться пополам. Разбиение массива размера $n$ на 2 части (операция `partition`) требует $n$ сравнений, значит имеет асимптотику $O(n)$. Алгоритм вызывает самого себя 2 ($O(1)$) раза на каждом шаге. Тогда:

$$T(n)=2T(n/2)+O(n)$$

$$M(n)=2M(n/2)+O(1)$$

Отсюда (пользуясь [этим вариантом теоремы](https://ru.wikipedia.org/wiki/%D0%9E%D1%81%D0%BD%D0%BE%D0%B2%D0%BD%D0%B0%D1%8F_%D1%82%D0%B5%D0%BE%D1%80%D0%B5%D0%BC%D0%B0_%D0%BE_%D1%80%D0%B5%D0%BA%D1%83%D1%80%D1%80%D0%B5%D0%BD%D1%82%D0%BD%D1%8B%D1%85_%D1%81%D0%BE%D0%BE%D1%82%D0%BD%D0%BE%D1%88%D0%B5%D0%BD%D0%B8%D1%8F%D1%85#:~:text=2%5B%D0%BF%D1%80%D0%B0%D0%B2%D0%B8%D1%82%D1%8C%20%7C%20%D0%BF%D1%80%D0%B0%D0%B2%D0%B8%D1%82%D1%8C%20%D0%BA%D0%BE%D0%B4%5D-,%D0%9E%D0%B1%D1%89%D0%B0%D1%8F%20%D1%84%D0%BE%D1%80%D0%BC%D0%B0,-%5B%D0%BF%D1%80%D0%B0%D0%B2%D0%B8%D1%82%D1%8C%20%7C%20%D0%BF%D1%80%D0%B0%D0%B2%D0%B8%D1%82%D1%8C%20%D0%BA%D0%BE%D0%B4%5D)):

$$a=2, b=2, c=1, c=\log_b a \quad \Rightarrow \quad T(n)=O(n\log n)$$

$$a=2, b=2, c=0, c=\log_b a \quad \Rightarrow \quad M(n)=O(\log n)$$

2. В худшем случае на каждом шаге алоритма массив будет делиться на 2 неравных, в одном из которых будет мало элементов (например, $1$), а в другом будут почти все оставшиеся, (например $n-1$). На каждом шаге алгоритм совершает 2 вызова ($O(1)$), один из которых в дальнейшем не развивает рекурсию. Тогда рекуррентное выражение будет иметь вид:

$$T(n)=T(n-1)+O(n)$$

$$M(n)=M(n-1)+O(1)$$

Выражение для $T$ задает алгебраическую прогрессию, поэтому из формулы для суммы алгебраической прогрессии $T(n)=O(n^2)$.

Решение рекуррентного выражения для $M$ дает сумму единиц, значит $M(n)=O(n)$.
